## 已确认的实现问题

P1：优先修复，影响训练成立条件；P2：正常迭代应修复；P3：低影响缺陷。证据等级分别标明浏览器复现、确定性探针和静态调用链，不把静态分析写成实机测试。

### B1 主音感钢琴题在作答前暴露答案

- 优先级：P1；证据：浏览器复现 + 源码。
- 位置：[RelativePitchTonicPracticeView.vue](../../src/views/RelativePitchTonicPracticeView.vue)，`keyboardMarks`（55行）、题干 `question.scale.id`（242行）和 `PianoKeyboard`（269行）。
- 触发：进入主音感钢琴题，题干直接显示 `G MAJOR`；选“只播放主音”时，第5个白键还在提示播放阶段高亮。音阶和其他提示同样通过 `activeNotes` 暴露可见键位。
- 本次操作：仅依据可见的 `G MAJOR`，待控件开放后点击第5个白键，页面显示“✓ 找到了主音 / G 大调的主音是 G”。无需通过听感保持主音。
- 影响：训练可退化为已知调名找键或记住高亮位置，与主音感目标冲突。隐藏琴键文字标签并不能消除泄露。
- 建议：练习答题前隐藏实际调名及题目音频的琴键高亮，反馈后再显示；学习页保留联动演示。若要保留视觉辅助，必须明确作为单独提示模式。
- 验收：主音题作答前的可见文本及可访问名称均不包含答案调名，题目播放不标出实际琴键；反馈仍揭示正确关系。

### B2 音频解锁失败仍被当作听题完成

- 优先级：P1；证据：实际控制器源码的隔离探针 + 页面调用链；未模拟真实浏览器权限拒绝。
- 位置：[useInstrumentPlayer.ts](../../src/composables/useInstrumentPlayer.ts)，`playTimeline`（118–155行）；[主音感](../../src/views/RelativePitchTonicPracticeView.vue) 与 [音级听辨](../../src/views/RelativePitchDegreePracticeView.vue) 的 `playCurrentQuestion`。
- 触发：`engine.unlock()` 返回 false；控制器虽然不调用音源，仍调度整条时间线并调用 `onComplete`。两种听辨页将状态改成 `answering`，允许提交和累计已完成题数。
- 探针：对当前控制器提供 `unlock: async () => false` 的假引擎，一步1ms时间线结束后得到 `onCompleteCalled: true`，错误文案仍为“你仍可继续答题”。
- 影响：没有听到题目也能完成听辨题。与 PRD 异常状态“未激活音频，不自动出听音题”不一致；视觉练习可降级继续，纯听辨不能照搬。
- 建议：播放结果区分成功、取消、不可用；听辨页在失败时保持待重试，不开放答案和计数，提供明确的启用声音入口。保留视觉模块继续练习的能力。
- 验收：分别验证 unlock 失败、采样失败但合成可用、取消/切题；只有真正可播放的完整题目结束后开放听辨答案。

### B3 唱名数字快捷键接受长按和组合键

- 优先级：P2；证据：对当前 `handleKeydown` 做确定性隔离调用。
- 位置：[SolfegeMemoryPractice.vue](../../src/components/SolfegeMemoryPractice.vue)，363–393行。
- 触发：数字作答题中长按正确数字；首项正确后 `repeat` 事件继续提交该数字，相邻项不同，因而下一项直接判错。Ctrl/Meta+数字和输入法组合期间的数字也会进入提交逻辑。
- 探针：分别传入 `repeat: true`、`ctrlKey: true`、`metaKey: true`、`isComposing: true` 的 `key: '1'` 事件，四种均调用 `submitAnswer`。
- 影响：无意判错并可能拦截浏览器快捷键；与键位/C 大调模块已有的过滤行为不一致。
- 建议：统一忽略重复事件、组合键及编辑控件中的输入；每次实际按下只提交一次。
- 验收：长按数字只作答一次；Ctrl/Meta/Alt+数字、输入法事件不提交；普通1–7继续可用。

### B4 二选一干扰音配额被钢琴题消耗

- 优先级：P2；证据：直接调用领域生成器的确定性探针。
- 位置：[relativePitch.ts](../../src/domain/relativePitch.ts)，182–192行；[relativePitch.test.ts](../../src/domain/__tests__/relativePitch.test.ts)，35–42行。
- 触发：生成器每道题都调用 `nextDistractorDegree()`，而钢琴题的音频不使用该字段。二选一实际看到的干扰音只是袋中的子集。
- 复现：seed=1，随机函数为 `seed = (Math.imul(1664525, seed) + 1013904223) >>> 0; return seed / 2**32`。循环生成直到收集6道 `type === 'choice'`，其干扰级数是 `[3, 4, 5, 2, 4, 5]`，只覆盖4种。
- 影响：文档承诺的二选一2–7级均衡未成立。现有测试统计所有题目的 `distractorDegree`，因此通过却没有覆盖实际呈现的配额。
- 建议：只在二选一题消耗干扰音袋；测试应先筛选真实呈现的二选一题，再检查每6道覆盖2–7。
- 验收：多个固定随机源下连续二选一袋覆盖全集；不影响十二调及两种题型的原有配额。

### B5 自由钢琴静音会传播到无音量控件的听辨页

- 优先级：P2；证据：静态跨路由调用链，尚未完成真实音频输出测量。
- 位置：[PianoToolView.vue](../../src/views/tools/PianoToolView.vue)，20行；[tonePianoAudio.ts](../../src/audio/tonePianoAudio.ts)，`setVolume` 与文件末尾共享实例；[useInstrumentPlayer.ts](../../src/composables/useInstrumentPlayer.ts) 的 `stop`。
- 触发：自由钢琴将音量调到0 → 返回首页 → 进入主音感/音级听辨。`setVolume` 改的是应用共享 Gain；离页只释放声音，不恢复音量；听辨页面也不设置音量或提供恢复控件。
- 影响：音频状态可以是 ready，播放时间线正常结束，但听不到题目。用户必须回工具页恢复音量或刷新应用。
- 建议：明确音量属于应用全局还是页面局部；全局则所有听音页可见并可恢复，局部则按进入/离开维护音量边界。不要仅改变错误提示掩盖静音。
- 验收：工具静音后进入听辨能清楚识别并解除静音，且不会悄悄提交无声题目。

### B6 首页连续通知被旧计时器提前清空

- 优先级：P3；证据：当前源码调用链。历史扫描曾报告，但当前仍未修复。
- 位置：[HomeView.vue](../../src/views/HomeView.vue)，`showNotice`（108–113行）。
- 触发：先打开一个占位入口提示，2秒后再点击另一个；第一条的2600ms计时器会在第二条出现约600ms时把它清空。
- 影响：第二条提示显示时间不足，用户可能没看清原因。组件卸载也未清理旧计时器。
- 建议：保存并取消上一条通知计时器，卸载时清理；或用通知代次防止旧回调修改新消息。
- 验收：连续触发不同提示时，每条最新提示均保留完整2600ms，旧回调不能清掉新通知。
