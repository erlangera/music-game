# 唱名记忆训练

- 状态：S1/S2 双向文字练习原型已实现
- 最近验证：2026-09-04
- 需求来源：[`../music-theory-ear-training-prd-v1.md`](../music-theory-ear-training-prd-v1.md)
- 当前实现：[`../../src/components/SolfegeMemoryPractice.vue`](../../src/components/SolfegeMemoryPractice.vue)

## 产品目的

模块一帮助中文简谱初学者快速建立首调唱名和简谱级数之间的双向映射。规范唱名统一为 `do re mi fa sol la si`；不要重新引入 `ti`。完整术语和领域不变量见 [`../domain/music-theory.md`](../domain/music-theory.md)。

当前练习刻意不加入具体调、音高、节奏或八度，每道题只要求完成一个方向的映射：

- 唱名 → 简谱：显示一个唱名，从随机排列的 `1–7` 中选择答案。
- 简谱 → 唱名：显示一个 `1–7` 数字，从随机排列的 `do–si` 中选择答案。

## 当前练习蓝图

| 规则 | 当前值 |
| --- | --- |
| 每轮题数 | 10 题 |
| 方向配额 | 两个方向各 5 题 |
| 连续方向 | 同一方向最多连续 2 题 |
| 映射分布 | 一轮内七组映射尽量均衡，相同唱名不连续出现 |
| 按钮内容 | 始终给出覆盖全集的 7 个答案 |
| 按钮顺序 | 每题洗牌，排除正序、倒序和同方向上一题的完全相同顺序 |
| 正确反馈 | 锁定按钮，显示完整映射，约 900ms 后自动进入下一题 |
| 错误反馈 | 标出所选答案和正确答案，显示完整映射，由用户确认进入下一题 |
| 结果 | 显示正确数、错误数和正确率，可返回首页或再练一组 |

随机排列必须在“准备新题”时生成并存入组件状态。不要在模板、渲染函数或会反复求值的派生状态中重新洗牌，否则用户作答期间按钮位置会变化，也无法还原错题。

## 输入与可访问性

- 两种题型都支持鼠标和触摸选择。
- 唱名 → 简谱题支持电脑键盘数字 `1–7`；数字直接代表答案语义，不代表随机按钮的位置。
- 简谱 → 唱名题当前不设置字母快捷键，避免 `sol`/`si` 冲突或把随机位置重新编码成顺序提示。
- 提交后立即锁定本题按钮，防止重复计分。
- 正误同时使用颜色、图标和文字表达。
- 错题反馈出现后，把键盘焦点移到“下一题”。
- 页面保持可见焦点，所有答案按钮都有可访问名称。

## 页面入口和状态边界

首页“今日推荐”的“开始训练”和学习路径“阶段 01”的“继续学习”都会进入 `/solfege` 路由；退出训练和结果页“返回首页”进入 `/`。路由使用 hash history，因此 GitHub Pages 上的实际 URL 形如 `/music-game/#/solfege`，可直接刷新并支持浏览器前进、后退。

题目、得分和进度只存在组件内存中：刷新、退出或关闭页面后不会保留。错题、掌握度、本地存储、可复现 seed 和跨会话学习记录仍属于规划能力。

## 后续声音模式

声音模式应复用同一映射、随机化和判分规则，只把视觉题干替换为唱名语音，并提供重播控制。播放 `do`、`re`、`mi` 等语音时不显示对应文字。

如果输入是没有唱名语音的具体音高，题目就不再是唱名记忆，而是功能音级听辨；此时必须先建立调性，避免把训练错误地变成绝对音高测试。

## 实现经验

- 双向混合不要使用“每题独立抛硬币”，否则小样本中可能几乎只有一个方向。应先建立固定的 5/5 方向配额，再洗牌并限制连续数量。
- 答案按钮随机化和题目内容随机化是两个独立约束，应分别建模。
- 反向题不能复用只接受数字的答案类型；当前实现显式区分 `Degree`、`SolfegeName`、`QuestionDirection` 和联合答案类型。
- 反馈文案统一使用 `唱名 = 数字`，无论题目方向如何，帮助用户反复看到同一规范映射。
- 正确题自动前进适合保持节奏；错题需要人工确认，保证用户有时间查看正确关系。
- 当前随机和判分仍在 Vue 组件内。继续增加难度、错题复现或自动化测试前，应把题目生成和评分提取到纯 TypeScript 领域模块。
